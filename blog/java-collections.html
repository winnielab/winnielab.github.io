深入理解 Java 集合框架：
从底层数据结构到面试实战

从接口语义和数据结构出发，拆解 ArrayList、HashMap、TreeMap、Queue 与并发集合，再把常见坑、工程选型和面试表达串成一套完整知识体系。

发布于 2026-10-18 约 42 分钟 Java · Collections · List · Map · Set · JUC
本文的版本边界

接口行为以 Java SE 25 API 为主要参考；HashMap 树化阈值、ArrayList 扩容等源码细节以当前 OpenJDK 实现为例。实现细节可能随 JDK 版本变化，不应当作 Collection 或 Map 接口的永久契约。

1. 集合框架到底在解决什么问题

数组能保存一组同类型数据，但长度固定，插入、删除、查找和并发控制都需要自行处理。Java 集合框架把常见数据结构抽象为接口，用统一方式表达“是否有序、能否重复、按位置还是按键访问、是否需要并发”等语义，并提供经过长期验证的实现。

面试中只背“ArrayList 底层是数组，LinkedList 底层是链表”远远不够。真正重要的是：业务操作模式是什么，接口承诺了什么复杂度和顺序语义，实现为了这些承诺付出了什么空间、复制、哈希或同步成本。

1.1 Collection、Collections 与 Map

  • Collection是集合层次的根接口，表示一组元素；List、Set、Queue 都由它扩展。
  • Collections是工具类，提供排序、查找、不可修改视图、同步包装等静态方法。
  • Map表示键值映射，不继承 Collection；它通过 keySet()、values()和entrySet()暴露集合视图。

1.2 JDK 21 的 Sequenced Collections

JDK 21 引入 SequencedCollection、SequencedSet和SequencedMap，为“存在明确相遇顺序”的集合统一提供首尾访问和反向视图，例如 getFirst()、getLast()、reversed()。List、Deque、LinkedHashSet、LinkedHashMap、TreeMap 等由此拥有更统一的顺序 API。

import java.util.ArrayList;
import java.util.List;

public final class SequencedDemo {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>(List.of("Ada", "Bob", "Cora"));

        System.out.println(names.getFirst());       // Ada，JDK 21+
        System.out.println(names.getLast());        // Cora
        System.out.println(names.reversed());       // [Cora, Bob, Ada]

        names.reversed().removeFirst();             // 视图写穿到底层列表，删除 Cora
        System.out.println(names);                  // [Ada, Bob]
    }
}

reversed()通常返回反向视图而不是独立副本，修改是否写穿以及操作是否受支持，要看具体实现和接口契约。

2. 先理解集合的共同契约

2.1 泛型：在编译期约束元素类型

泛型让 List<User>只能按 User 语义读写，减少运行期类型转换错误。集合 API 中常见的 ? extends T表示主要作为 T 的生产者读取，? super T表示可以安全写入 T，即常说的 PECS：Producer Extends，Consumer Super。

2.2 equals 与 hashCode 决定“相等”

List 的查找、Set 的去重、Map 的键匹配最终都依赖相等性。对于 HashSet 和 HashMap，两个对象若 equals相等，就必须拥有相同 hashCode；否则相等对象可能进入不同桶，导致查找失败或出现逻辑重复。

import java.util.HashMap;
import java.util.Map;

public final class KeyContractDemo {
    record UserKey(long tenantId, long userId) {}

    public static void main(String[] args) {
        Map<UserKey, String> users = new HashMap<>();
        users.put(new UserKey(7, 42), "Young");

        // record 根据组件生成一致的 equals 与 hashCode
        System.out.println(users.get(new UserKey(7, 42))); // Young
    }
}

作为哈希键的字段最好不可变。键放入 Map 后再修改参与 equals/hashCode的字段，它所在桶不会自动迁移，之后即使拿同一个对象查询，也可能找不到。

2.3 有序、排序与相遇顺序不是一回事

  • 有索引顺序：List 按位置保存元素。
  • 插入顺序：LinkedHashSet、默认 LinkedHashMap 迭代时保持插入顺序。
  • 访问顺序：LinkedHashMap 可按最近访问顺序维护链表，适合构建 LRU。
  • 排序顺序：TreeSet、TreeMap 按自然顺序或 Comparator 排序。
  • 未指定顺序：HashMap、HashSet 不承诺迭代顺序，即使某次运行看起来稳定也不能依赖。

排序集合的 Comparator 最好与 equals一致。如果比较结果为 0，但 equals为 false，TreeSet 仍会把两个元素当作同一个排序位置，这往往是面试中的追问点。

2.4 fail-fast 不是线程安全机制

ArrayList、HashMap 等迭代器通常维护结构修改计数。迭代期间如果集合被绕过迭代器结构性修改，可能抛出 ConcurrentModificationException。但官方契约明确说明这是尽力而为的错误检测，不能保证每次都抛，也不能用异常代替同步。

import java.util.ArrayList;
import java.util.List;

public final class SafeRemovalDemo {
    public static void main(String[] args) {
        List<Integer> values = new ArrayList<>(List.of(1, 2, 3, 4));

        values.removeIf(value -> value % 2 == 0);
        // 或使用 Iterator.remove()，不要在增强 for 中直接 values.remove(...)

        System.out.println(values); // [1, 3]
    }
}

3. List：位置、顺序与重复元素

3.1 ArrayList：连续引用数组

ArrayList 使用可扩容数组保存元素引用。按索引读取只需计算偏移，通常是 O(1)；尾部追加是摊销 O(1)；中间插入或删除需要移动后续元素，通常是 O(n)。连续布局还具有较好的 CPU 缓存局部性，所以它常是普通 List 的默认选择。

容量与 size不同：size 是已有元素数，capacity 是底层数组可容纳的引用数。扩容要申请新数组并复制旧元素。API 只保证追加的摊销常数复杂度，并不把具体增长倍率作为契约；当前 OpenJDK 常采用约 1.5 倍增长。已知数据规模时传入初始容量或调用 ensureCapacity可减少复制。

3.2 LinkedList：双向链表不等于更快

LinkedList 的每个节点保存元素及前后节点引用。已持有节点位置时，链接和删除可以是 O(1)；但公开 API 常先按索引从头或尾遍历定位节点，因此 get(index)和按位置插入总体仍是 O(n)。每个节点有额外对象与引用开销，内存局部性也差。

3.3 Vector、Stack 与 CopyOnWriteArrayList

Vector和Stack是早期同步容器，新代码通常不以它们为首选。栈语义优先用 Deque与ArrayDeque。CopyOnWriteArrayList每次写操作复制整个数组，迭代器读取创建时的快照，适合读远多于写、元素不多且需要稳定遍历的监听器列表；写频繁或元素很大时成本会非常高。

4. Set：唯一性由什么决定

4.1 HashSet 与 LinkedHashSet

HashSet 本质上借助 HashMap 的键实现去重，元素作为 key，value 使用内部占位对象。因此它的相等性、哈希分布、平均复杂度和扩容行为与 HashMap 紧密相关。它允许一个 null 元素，但不承诺迭代顺序。

LinkedHashSet 在哈希结构之外维护相遇顺序，通常保持插入顺序，代价是额外链接和内存。需要“唯一且保持输入顺序”时，它比“HashSet 去重后再排序”更直接。

4.2 TreeSet 与排序一致性

TreeSet 通常由 TreeMap 支撑，按自然顺序或 Comparator 维护有序集合，增删查通常是 O(log n)。它判断重复主要依据比较结果是否为 0，而不是再调用 equals。因此比较器要构成稳定的全序，最好与 equals 一致。

4.3 三种 Set 的选择

01

HashSet

只关心唯一性与平均 O(1) 查找，不依赖迭代顺序。

02

LinkedHashSet

唯一性之外，还要保留插入顺序或使用 JDK 21+ 首尾操作。

03

TreeSet

需要排序、范围查询、最小值、最大值或相邻元素导航。

5. Map：面试最常追问的集合

5.1 HashMap 的 put 与 get

HashMap 用桶数组保存映射。访问时先对 key 的 hashCode 做扰动，结合表长计算桶位置；桶为空则直接插入，桶中已有节点则比较哈希与 key 相等性。冲突少时，get/put平均接近 O(1)；极端冲突、恶意哈希或频繁扩容都会改变实际成本。

5.2 链表何时树化

从 JDK 8 起，OpenJDK HashMap 在严重冲突时可以把桶内链表转换为红黑树，降低最坏查找成本。当前实现常见常量为：树化阈值 8、反树化参考阈值 6、允许树化的最小表容量 64。达到 8 个节点并不必然立刻树化；表容量不足时通常优先扩容。

不要把 8、6、64 当作 Map 接口契约

这些数字来自当前 OpenJDK HashMap 源码，是常见面试考点，但可以随实现变化。业务代码不应依赖桶类型或树化阈值。

5.3 容量、负载因子与扩容

默认 HashMap 常使用 0.75 负载因子，在时间与空间之间折中。元素数超过 capacity × loadFactor附近的阈值后扩容。当前实现通常保持容量为 2 的幂，使索引计算与扩容拆分更高效。已知预计条目数时应合理初始化容量，避免多次 resize；也不要盲目给出巨大容量，因为遍历成本和内存占用都受桶数组大小影响。

HashMap 允许一个 null key 和多个 null value，所以 get(key) == null无法区分“没有映射”和“映射值就是 null”，需要时使用 containsKey。

5.4 可变键为什么危险

import java.util.HashMap;
import java.util.Map;
import java.util.Objects;

public final class MutableKeyDemo {
    static final class Key {
        private String code;

        Key(String code) { this.code = code; }
        void setCode(String code) { this.code = code; }

        @Override public boolean equals(Object other) {
            return other instanceof Key key && Objects.equals(code, key.code);
        }

        @Override public int hashCode() { return Objects.hash(code); }
    }

    public static void main(String[] args) {
        Map<Key, String> map = new HashMap<>();
        Key key = new Key("A");
        map.put(key, "value");

        key.setCode("B");
        System.out.println(map.get(key)); // 很可能是 null：桶位置已与新 hash 不匹配
    }
}

5.5 LinkedHashMap 与 LRU

LinkedHashMap 在 HashMap 节点之外维护双向顺序链。默认按插入顺序；构造时启用 access-order 后，读取也会把条目移动到顺序末尾，可结合 removeEldestEntry实现简单的有界 LRU。它不是线程安全缓存，也不提供 TTL、权重、统计或防击穿能力，生产缓存通常优先使用成熟缓存库。

import java.util.LinkedHashMap;
import java.util.Map;

public final class LruCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LruCache(int capacity) {
        super(capacity, 0.75f, true); // true：访问顺序
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }
}

5.6 TreeMap 与范围查询

TreeMap 通常使用红黑树维护按 key 的全序，get/put/remove是 O(log n)，并提供 floorKey、ceilingKey、subMap等导航与范围视图。自然排序下 key 必须可比较；自定义 Comparator 要能接受所有键，并尽量与 equals 一致。

如果只要求哈希查找，不要为了“看起来有序”使用 TreeMap；如果需要排行榜区间、时间窗口索引或最邻近键，TreeMap 的排序能力才有价值。

6. Queue、Deque 与 PriorityQueue

6.1 两组队列 API

操作失败抛异常失败返回特殊值
插入add(e)offer(e)
删除队首remove()poll()
查看队首element()peek()

容量受限或并发队列通常优先使用 offer一组 API，调用方可以显式处理“当前无法插入”。BlockingQueue 还提供可阻塞的 put/take和带超时操作。

6.2 ArrayDeque：队列和栈的常用选择

ArrayDeque 使用循环数组支持两端操作，通常比 LinkedList 更节省内存、局部性更好。作为栈使用 push/pop/peek，作为队列使用 offer/poll/peek。它不允许 null，因此 null 可以安全表示“没有元素”。

6.3 PriorityQueue：堆顶有序，不是整体有序

PriorityQueue 通常使用二叉堆。peek查看优先级最高元素是 O(1)，offer/poll通常是 O(log n)。它的迭代顺序不保证排序；要按优先级依次取得元素，必须持续 poll或复制后排序。

import java.util.Comparator;
import java.util.PriorityQueue;
import java.util.Queue;

public final class TaskQueueDemo {
    record Task(String name, int priority) {}

    public static void main(String[] args) {
        Queue<Task> tasks = new PriorityQueue<>(
                Comparator.comparingInt(Task::priority).reversed());

        tasks.offer(new Task("report", 2));
        tasks.offer(new Task("payment", 10));
        tasks.offer(new Task("email", 1));

        while (!tasks.isEmpty()) {
            System.out.println(tasks.poll()); // payment, report, email
        }
    }
}

7. 并发集合：线程安全不等于所有组合操作原子

普通 ArrayList、HashMap 和 HashSet 都不是线程安全的。多线程共享且存在写操作时，要么把状态封装在锁内，要么选择并发集合。上一篇《Java 锁机制》工程选型讨论了 JVM 本地锁边界；这里聚焦集合自身提供的并发语义。

7.1 synchronized 包装器

Collections.synchronizedList等包装器让单个方法通过同一互斥锁串行执行，但遍历仍需要手动同步整个迭代过程。多个方法组成的“先检查再执行”也不会自动成为一个原子事务。

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public final class SynchronizedViewDemo {
    private final List<String> names =
            Collections.synchronizedList(new ArrayList<>());

    public void printAll() {
        synchronized (names) {
            for (String name : names) {
                System.out.println(name);
            }
        }
    }
}

7.2 ConcurrentHashMap

ConcurrentHashMap 支持高并发读取和更新，读取通常不需要锁住整张表。JDK 8+ 的实现不再采用早期 Segment 分段锁结构，而是在桶级结合 CAS、synchronized、链表 / 红黑树和协作扩容等机制。它不允许 null key 或 null value，避免并发语境下“没有映射”和“映射为 null”的歧义。

线程安全的方法应优先使用原子复合 API，例如 putIfAbsent、compute、merge。自己写 containsKey后再put仍存在检查与写入之间的竞态。

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.LongAdder;

public final class WordCounter {
    private final Map<String, LongAdder> counts = new ConcurrentHashMap<>();

    public void record(String word) {
        counts.computeIfAbsent(word, ignored -> new LongAdder()).increment();
    }

    public long count(String word) {
        LongAdder counter = counts.get(word);
        return counter == null ? 0L : counter.sum();
    }
}

映射函数应尽量短、无阻塞且避免递归修改同一映射。迭代器是弱一致的：可以与更新并发，不抛出普通 fail-fast 异常，但遍历结果可能反映部分更新，不是时间点快照。

7.3 CopyOnWrite 与跳表

  • CopyOnWriteArrayList：写时复制，迭代器是创建时快照；适合读极多写极少的监听器、配置快照。
  • ConcurrentLinkedQueue：非阻塞并发队列，适合不需要容量限制和阻塞等待的任务流。
  • BlockingQueue：生产者—消费者、背压和线程池工作队列；有界队列通常更容易控制资源。
  • ConcurrentSkipListMap：并发有序 Map，支持范围查询，典型复杂度 O(log n)。

8. 视图、不可修改与不可变集合

8.1 List.of 与 copyOf

List.of、Set.of、Map.of创建不可修改集合，并拒绝 null；Set 和 Map 工厂也拒绝重复元素 / key。List.copyOf(source)得到源集合当前内容的不可修改副本语义，后续修改 source 不应影响结果。

8.2 unmodifiable 只是只读视图

Collections.unmodifiableList(source)禁止通过视图写入，但 source 仍可被其他代码修改，视图会反映变化。它不是防御性副本，更不自动获得线程安全。

8.3 Arrays.asList 与 subList

import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.List;

public final class ViewDemo {
    public static void main(String[] args) {
        String[] array = {"A", "B"};
        List<String> fixed = Arrays.asList(array);
        fixed.set(0, "X");          // 允许替换，array[0] 同时变为 X
        // fixed.add("C");          // UnsupportedOperationException：长度固定

        List<String> source = new ArrayList<>(List.of("A", "B"));
        List<String> view = Collections.unmodifiableList(source);
        source.add("C");            // view 现在也能看到 C

        List<String> snapshot = List.copyOf(source);
        source.add("D");            // snapshot 不受影响
    }
}

subList也是原列表的区间视图，不是新 ArrayList。对子列表的结构修改会写回原列表；原列表被视图之外的路径结构性修改后继续使用旧 subList，行为可能失败。跨层传递数据时，明确创建 new ArrayList<>(subList)通常更安全。

9.2 后端开发常见场景

01

数据库查询结果

通常顺序遍历，优先 ArrayList；能预估行数时设置容量。

02

按 ID 快速定位

使用 HashMap；key 尽量不可变，并实现稳定 equals/hashCode。

03

保持输入顺序去重

使用 LinkedHashSet，而不是 HashSet 后猜测迭代顺序。

04

排行榜和范围查询

单 JVM 可评估 TreeMap；真实大规模排行榜通常需要数据库或专用存储。

05

生产者—消费者

优先有界 BlockingQueue，通过容量形成背压，避免无界积压耗尽堆。

06

并发注册表与计数

ConcurrentHashMap 配合 compute、merge 或 LongAdder，避免检查—再执行竞态。

9.3 高频错误清单

  • 依赖 HashMap / HashSet 当前观察到的迭代顺序。
  • 把 LinkedList 的中间插入笼统说成 O(1)，忽略定位节点的 O(n)。
  • HashMap key 可变，或 equals 与 hashCode 不一致。
  • 认为 ConcurrentHashMap 能让多次调用自动组成事务。
  • 在并发修改中依赖 ConcurrentModificationException 保证正确性。
  • 误以为 Arrays.asList 是普通 ArrayList，或把 unmodifiable 视图当作不可变副本。
  • 使用无界集合承接不受控流量，最终把队列积压演变成堆 OOM。

10. Java 集合高频面试问题

每题先给可直接口述的回答，再补充追问需要的边界。

01Collection 和 Collections 有什么区别？

面试回答：Collection 是 List、Set、Queue 等集合接口的根接口；Collections 是工具类，提供排序、查找、同步包装和不可修改视图等静态方法。Map 不继承 Collection。

原理补充：Map 通过 keySet、values、entrySet 提供集合视图。

02ArrayList 和 LinkedList 有什么区别？

面试回答：ArrayList 基于可扩容数组，随机访问 O(1)、中间移动 O(n)，内存局部性好；LinkedList 是双向链表，按索引访问 O(n)，节点开销较大，只有已经定位节点后的链接操作才是 O(1)。

原理补充：大多数普通 List 场景优先 ArrayList；双端队列优先 ArrayDeque。

03ArrayList 扩容机制是什么？

面试回答：容量不足时创建更大的数组并复制旧元素，尾部追加因此是摊销 O(1)。当前 OpenJDK 常按约 1.5 倍增长，但具体倍率不是 List API 契约。

原理补充：预估数据量时指定初始容量或 ensureCapacity 能减少复制和临时数组。

04为什么 ArrayList 查询快、插入慢？

面试回答：按索引可直接计算数组偏移，所以 get 是 O(1)；中间插入要把后续引用整体右移，所以是 O(n)。

原理补充：尾部插入通常不移动现有元素，只在扩容时复制。

05HashMap 的底层结构是什么？

面试回答：JDK 8+ OpenJDK HashMap 使用桶数组，桶内通常是链表，严重冲突且容量足够时可转为红黑树。通过 hash 定位桶，再用 hash 与 equals 匹配 key。

原理补充：这是实现细节；树化常见阈值 8、最小容量 64，但不能由业务依赖。

06HashMap 为什么容量通常是 2 的幂？

面试回答：当前实现可用位运算快速计算桶索引，扩容翻倍时节点只需根据新增高位留在原索引或移动固定偏移，也有利于均匀利用哈希位。

原理补充：构造时给出的容量会被实现调整，不代表底层表立刻分配到该大小。

07HashMap 的负载因子为什么常是 0.75？

面试回答：它是在桶数组空间和冲突概率之间的经验折中。更低会占更多空间但冲突少，更高节省桶空间但链表或树冲突增加。

原理补充：不要脱离数据规模和哈希质量随意修改。

08HashMap 为什么线程不安全？

面试回答：put、resize、链表或树维护都涉及多步共享状态更新，没有并发同步；并发写可能丢更新、覆盖状态或得到不一致结果。

原理补充：不要只背早期 JDK 的“扩容死循环”，现代实现问题表现可能不同，结论仍是不能并发共享写。

09HashMap 和 Hashtable 有什么区别？

面试回答：HashMap 非线程安全，允许 null key/value；Hashtable 是旧式同步容器，不允许 null，方法级同步并不适合现代高并发组合操作。新代码通常用 HashMap 或 ConcurrentHashMap。

原理补充：ConcurrentHashMap 不是简单给整张表加一把锁。

10HashMap 和 ConcurrentHashMap 有什么区别？

面试回答：HashMap 用于非并发或外部同步场景；ConcurrentHashMap 提供线程安全的单操作和 compute、merge 等原子复合 API，高并发读取通常不锁整表，并禁止 null key/value。

原理补充：JDK 8+ 实现结合 CAS 和桶级同步，不是 JDK 7 的 Segment 架构。

11ConcurrentHashMap 的 size 准确吗？

面试回答：在没有并发更新时有明确结果；并发更新期间，聚合状态可能是瞬时估计，更适合监控而不是流程控制。

原理补充：并发逻辑不要依赖“先 size 再操作”维持不变式。

12equals 和 hashCode 为什么必须一起重写？

面试回答：哈希集合先用 hash 定位桶，再用 equals 判断逻辑相等。equals 相等却 hash 不同会落入不同桶，导致查找失败或重复。

原理补充：相同 hash 不要求 equals 相等，冲突由桶内比较解决。

13HashSet 如何实现去重？

面试回答：HashSet 通常使用 HashMap，把元素作为 key、内部常量对象作为 value，因此由 hashCode 和 equals 决定唯一性。

原理补充：LinkedHashSet 增加顺序链，TreeSet 使用排序比较结果判重。

14TreeMap 和 HashMap 如何选择？

面试回答：只需按键平均 O(1) 查找用 HashMap；需要键排序、范围查询、floor/ceiling 等导航操作用 TreeMap，复杂度通常 O(log n)。

原理补充：TreeMap Comparator 应稳定并尽量与 equals 一致。

15什么是 fail-fast？

面试回答：普通集合迭代器检测到预期之外的结构修改时会尽快抛 ConcurrentModificationException，用于暴露错误。

原理补充：这是 best-effort 检测，不保证每次抛出，也不提供线程安全。

16CopyOnWriteArrayList 适合什么场景？

面试回答：适合读远多于写、集合不大、遍历需要稳定快照的场景，例如监听器列表。每次写都会复制数组，写频繁时成本很高。

原理补充：迭代器看不到创建后的修改，也不支持 iterator.remove。

17ArrayDeque 为什么通常比 Stack 更推荐？

面试回答：Stack 继承 Vector，是旧式同步设计；ArrayDeque 直接提供 Deque 的栈和队列语义，通常开销更低、API 更清晰。

原理补充：ArrayDeque 不允许 null，也不是线程安全的。

18PriorityQueue 是完全有序的吗？

面试回答：不是。它只保证队首是当前优先级最高或最低元素，迭代顺序不保证排序；按顺序消费要持续 poll。

原理补充：常见实现是二叉堆，peek O(1)，offer/poll O(log n)。

19Arrays.asList、List.of、new ArrayList 有什么区别？

面试回答：Arrays.asList 是数组支持的定长视图，可 set 但不能增删；List.of 是不可修改且拒绝 null 的集合；new ArrayList 创建可变独立列表。

原理补充：需要从数组得到普通可变列表，可用 new ArrayList<>(Arrays.asList(array))。

20如何选择合适的 Java 集合？

面试回答：先判断按位置、按 key、唯一性还是队列语义，再判断是否需要顺序、排序、范围查询和并发；最后结合数据规模、复杂度和内存成本选择实现。

原理补充：普通 List 优先 ArrayList，哈希索引用 HashMap/HashSet，排序用 Tree 系列，双端操作用 ArrayDeque，并发共享写选择原子复合 API或锁封装。

结语：集合选型先看语义，再看实现

Java 集合不是类名记忆题。List、Set、Map 和 Queue 先表达数据关系；数组、链表、哈希表、红黑树、堆和跳表再决定复杂度与空间代价；同步、快照或无锁算法最后决定并发语义。

面试时给出结论后，要主动补上条件：平均还是最坏复杂度、接口契约还是 OpenJDK 实现、单线程还是并发、视图还是副本。实际开发中也按同样方式思考，通常就能避开“用错集合导致慢、乱序、丢数据或 OOM”的问题。
